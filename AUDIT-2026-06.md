## 🚨 À traiter EN PRIORITÉ (P0 — avant tout scale/launch payant)

1. **[Sécu-C] `/admin/*` sans garde serveur.** `middleware.js:29` ne fait aucune auth ; la vérif admin est **client only** (`app/admin/layout.js:45`) → contournable via payload RSC / curl. → Garde session serveur (middleware `@supabase/ssr`) ou redirection RSC avant rendu.
2. **[Sécu-C] `CRON_SECRET` en query param** (`app/api/sentry-test/route.js:9`, doc curl). Loggable (Vercel/CDN/Referer) → déclenche tous les crons (emails/push de masse). → Header `Authorization` + secret dédié `SENTRY_TEST_SECRET` ; gater la route hors prod.
3. **[Sécu-H] RLS manquantes/incohérentes** : `referrals` et `rithmic_credentials` absents de `supabase-schema.sql` (vérifier RLS activée en prod) ; `announcements` policy sur `is_active` alors que colonne = `active` (`supabase-schema.sql:455`) → annonces cassées **ou** policy non fonctionnelle.
4. **[Sécu-H] `resolve_username_to_email` exécutable par tout `authenticated`** (`supabase-schema.sql:284`) → énumération d'emails illimitée en contournant le rate-limit API. → `revoke execute … from authenticated`.
