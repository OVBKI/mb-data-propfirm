## 🔴 PRIORITÉ 0 — Bugs réels en production (corriger d'abord)

Ces bugs sont sur **`main`** (non touchés cette session) — vrais défauts fonctionnels :

1. **Drawdown Guardian cassé** (`app/api/cron/drawdown-guardian/route.js:25-40`)
   - `initialBalance = acct.balance` (balance courante) au lieu de la taille du plan → `roomPct` faux : un compte sain n'alerte jamais, l'alerte ne sort que quand le compte est déjà quasi mort. `plan_size` jamais utilisé.
   - `{error}` ignoré sur la requête + `.in('status', ['Challenge','Financé'])` exclut les comptes stockés `'Funded'`.
   - **Fix** : `roomPct = (balance - dd_floor) / planSizeNum(plan_size)` ; vérifier l'erreur ; inclure toutes les orthographes de statut.

2. **TradesPage — Long affiché comme SHORT** (`components/TradesPage.js:649,676`)
   - Les vues **Compact** et **Table** comparent `side === 'long'` (minuscule) alors que les données sont `'Long'`/`'Short'` → **tout Long s'affiche rouge ↘ SHORT**. La vue Carte est correcte.
   - **Fix** : comparer `'Long'`/`'Short'` (ou normaliser `.toLowerCase()` des 2 côtés).

3. **TradesPage — colonne R toujours vide** (`components/TradesPage.js:677,885`)
   - Lit `e.r_multiple` qui **n'est jamais écrit** (absent du schéma et des payloads). Compact/Table affichent « — ».
   - **Fix** : calculer via `computeRMultiple(...)` comme la vue Carte.

4. **import-lab met à jour le MAUVAIS compte** (`app/app/(main)/import-lab/page.js:693,296`)
   - L'auto-match cherche dans **tous** les comptes (sans filtre firme ni statut) → peut écraser un compte d'une autre firme / un compte Financé. Le filtre du dropdown est cosmétique.
   - **Fix** : passer la liste filtrée (firme + statut) au matcher, ou re-valider `mapping.accountId` avant update.

5. **delete-account — PII orpheline (RGPD)** (`app/api/auth/delete-account/route.js:33-43`)
   - Si une suppression de table échoue (juste `console.error`), le code supprime quand même l'utilisateur auth et renvoie `success:true` → données orphelines, aucun retry possible.
   - **Fix** : agréger les erreurs et **échouer avant** de supprimer l'utilisateur auth.

6. **Importers — virgule décimale européenne corrompue ×100** (`lib/importers/rithmic-pnl.js:120`, `rithmic-dashboard.js:61`)
   - `replace(/[",\s]/g,'')` transforme `1234,56` (locale EUR) en `123456`. Le dashboard lit `Account Currency` qui peut être EUR → balances/DD/PnL ×100.
   - **Fix** : détecter le séparateur décimal.

7. **onboarding-emails — compteur jamais incrémenté / risque de renvoi** (`app/api/cron/onboarding-emails/route.js:68-88`)
   - `.single()` en erreur (profil absent) ignoré → `alreadySent=0`, email envoyé, puis `update().eq(...)` matche 0 ligne → `onboarding_emails_sent` n'avance pas → renvoi au prochain run.
   - **Fix** : upsert le compteur, vérifier `{error}`, gater `alreadySent >= step+1`.

8. **Health — math à vérifier** : PayoutPipeline `hitsTarget` (`PayoutPipeline.js:44,53`) et ConsistencyMonitor (dénominateur = PnL net total, pas jours gagnants) (`ConsistencyMonitor.js:103`) peuvent mal classer. **À valider** contre les règles réelles des firmes.

9. **import-lab — `liquidated_at` jamais nettoyé** (`import-lab/page.js:872-876`) : un compte re-devenu sain reste `Échoué` et disparaît du Health.

## ⚡ PERF & ARCHITECTURE — 58/100

**HIGH**
- **`contextValue` non mémoïsé** (`(main)/layout.js:481-514`) : objet recréé à chaque render → **les 19 pages `useApp()` re-render** à chaque frappe de recherche / toast / ouverture de modal. Pire déclencheur : la saisie champ-par-champ dans le modal compte re-render toute l'app.
  **Fix** : `useMemo` la value, `useCallback` les actions, et **sortir l'état UI volatile** (`searchQ`, `toast`, modals) du provider (split en `AppData` / `AppUi`).
- **Full re-fetch après chaque mutation** (`layout.js` toutes les CRUD → `loadFirms()`) : renommer 1 compte = 3+ allers-retours + re-tri de tout l'arbre. **Fix** : updates optimistes / re-fetch ciblé.
- **N+1 billing** (`layout.js:198-218`) : `select('*')` de tous les comptes + 1 UPDATE par compte mensuel à chaque load. **Fix** : 1 RPC SQL set-based, ou laisser le cron.
- **Monolithe `layout.js` (834 l.)** : auth + données + billing + rates + export + calcul alertes + 6 modals inline. **Fix** : extraire modals + hook `useFirmsData()` + sélecteurs mémoïsés (< 150 l.).

**MEDIUM** : alertes/bills calculées inline non-mémoïsées (`:443-478`) ; `buildEventMap` non-mémoïsé (dashboard) ; **i18n.js (~105 Ko) shippé sur chaque page** (les 2 locales) ; **Sentry Replay chargé eagerly** (~50 Ko). 
**Bon** : chart.js en dynamic import partout, ISR sur 70+ pages SEO, listes lourdes (Trades/Journal) bien mémoïsées en interne, cleanup auth OK.
